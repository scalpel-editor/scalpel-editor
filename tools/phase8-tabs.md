# Phase 8 tabs plan

## Goal

Add one tabbed document workspace to the existing Wayland window. Each tab owns independent text, undo history, save point, file path, selection, and scroll position while the process keeps one `ApplicationEditor`, one renderer, one EGL context, and one Wayland toplevel.

Tabs are part of Phase 8 and should land before external-file change detection and conflict handling. Those policies need per-document identity and pending-action state, so implementing them against the current single-document globals would create work that tabs immediately replace.

## Current boundary and deficiency

`ApplicationEditor` currently owns one Scintilla `Document` through `Editor::pdoc`. `LoadInitialBuffer`, `Text`, `Modified`, and `MarkSaved` operate only on that active document. The retained local Scintilla implementation already has `Editor::SetDocPointer`, intrusive `Document::AddRef` / `Release`, document-local undo and save-point state, serialized selections, and named vertical and horizontal scroll operations.

One editor must switch among retained documents instead of constructing an editor per tab. `ApplicationEditor` owns the window-facing renderer, frame damage, clipboard, primary selection, IME, tickers, and idle work; duplicating it would duplicate state that belongs to the one Wayland surface.

The current file path, portal result handling, save policy, dirty prompt transitions, and accepted-close state are local variables and free functions in `app/main.cxx`. This is already a testability deficiency: the application tests cover the pieces, but not the complete open, save, prompt, and close workflow. Tabs should fix that boundary instead of adding more state to `main`.

## Product behavior

- Startup contains one clean untitled tab. Ctrl+N and the tab-strip add button create another untitled tab with a stable display number.
- Ctrl+O opens every accepted portal path in its own tab. Opening a path already present in the workspace selects that tab instead of creating a second editor for the same path. Initial duplicate detection uses the normalized absolute path returned by the portal; aliases through different symlinks remain part of the later external-file identity work.
- Ctrl+S saves the active tab and Ctrl+Shift+S starts Save As for the active tab. A delayed Save As result is applied to the tab that initiated it even when another tab became active.
- Ctrl+W and a tab close button close the requested tab. A clean tab closes immediately; a dirty tab becomes active and receives Save / Discard / Cancel. Closing the last tab creates a fresh untitled tab instead of quitting the window.
- A compositor close request walks dirty tabs in visible order, prompting one at a time. Save or Discard advances; Cancel aborts the whole window close. Required-global loss remains a force close without prompts.
- Ctrl+Tab and Ctrl+Shift+Tab cycle tabs. Left click activates a tab. The active tab is always kept visible in an overflowed strip; pointer wheel over the strip scrolls it horizontally. Drag reordering, tab detaching, pinned tabs, sessions across launches, split views, and recently-closed-tab history are out of scope.
- Labels use the base file name or the stable untitled name and show a dirty marker. A close affordance is always available on the active tab and appears on a hovered inactive tab.

## Ownership and lifecycle

`ApplicationEditor` gains an opaque document ID and a retained-document table. Each entry owns one Scintilla `Document` reference plus the serialized selection, first visible line, and horizontal offset that `SetDocPointer` resets. Activating an entry snapshots the outgoing view, cancels tentative IME input, invalidates asynchronous paste generations, switches the watched document, restores the incoming view, recomputes the line-number margin, refreshes text-input state, and redraws. Closing releases exactly the table reference after another document is active.

The editor host exposes text, modified state, and mark-saved operations by document ID as well as active-document convenience operations. This lets a portal result finish a Save As on its initiating tab without temporarily changing the visible tab. Undo history and save points stay in Scintilla `Document`; file path, title, untitled number, and pending application actions stay in the application workspace.

A focused `DocumentWorkspace` owns ordered tabs, the active tab ID, paths, untitled numbering, portal request intents, and the dirty-close sequence. It uses `ApplicationEditor` for document bytes and state but owns no Wayland or drawing objects. It returns specific requests such as show Open, show Save As, refresh tabs, or accept window close; `main` performs those requests against `WaylandWindow`. This is an application workflow object, not a general UI framework.

Portal operations must be correlated by stable IDs, never vector indexes. `WaylandFileDialog::Show` and `WaylandWindow::ShowFileDialog` should return the request ID already allocated by `WaylandFileDialogState`, and the workspace should map that ID to Open or to Save As for a particular tab ID. Results for a tab that no longer exists are ignored. The Open request enables the portal's multiple-file option only after its locally available contract or source has been read.

The permanent tab strip reserves a fixed logical-height rectangle above Scintilla's client rectangle. Input in that rectangle is intercepted before editor pointer handling. Permanent opaque chrome paints only when its own damage intersects the repaint; it must not use the modal overlay's full-client/full-swap path on every editor frame. The existing translucent unsaved card remains the modal overlay and draws above both tabs and editor content.

## Commit sequence

1. **Extract the document workflow from main.** Move the current single-document path, open/save result handling, dirty-prompt transition, and accepted-close decisions into a focused `DocumentWorkspace` with headless workflow tests; leave event delivery, rendering, and Wayland calls in `main`. Preserve current behavior in this commit. Build `documentWorkspaceTest` and run `"document workspace single-document*"`.
2. **Retain tab documents in ApplicationEditor.** Add opaque document IDs, balanced Scintilla document retention, active-document switching, full selection and scroll snapshots, and by-ID text/dirty/save-point operations. Cancel IME and invalidate pending clipboard and primary-selection paste generations on a switch. Extend `applicationHostTest` for independent text, undo, save points, selections, scrolling, reference release, and stale asynchronous results; build `applicationHostTest` and run `"production editor document switching*"`.
3. **Add the multi-document workspace model.** Replace the single path with ordered stable tab records, active selection, untitled numbering, new/activate/cycle/close operations, dirty labels, exact normalized-path duplicate selection, and the invariant that a running workspace always has at least one tab. Opening a file creates a tab instead of replacing the active buffer, so delete `UnsavedPending::Open`. Build `documentWorkspaceTest` and run `"document workspace tabs*"`.
4. **Route portal results to stable tab IDs.** Return portal request IDs from `Show`, record Open and per-tab Save As intents, support all accepted Open paths, enable verified portal multi-select, apply delayed Save As to its initiating tab, and ignore results whose intent or tab no longer exists. Extend `waylandPortalTest` and `documentWorkspaceTest`; build and run `"Wayland file dialog request IDs*"` and `"document workspace portal routing*"`.
5. **Close dirty tabs and windows in sequence.** Replace the close/open enum with a close-tab or close-window operation carrying a tab ID, activate the document named by the card, preserve the prompt across Save As failure or cancellation, advance through every dirty tab on window close, and abort the sequence without losing tabs on Cancel. Build `unsavedChangesPromptTest` and `documentWorkspaceTest`; run `"UnsavedChangesPrompt tab close*"` and `"document workspace window close*"`.
6. **Draw and hit-test the tab strip.** Add deterministic logical layout, truncation, dirty and hover states, close and add affordances, overflow scrolling, and an opaque painter using the existing renderer and system-ui font. Keep layout and hit testing independent from Wayland. Build a focused `tabStripTest` and run `"tab strip*"`, including image checks for active, dirty, overflowed, hovered, and scaled layouts.
7. **Reserve editor space for permanent chrome.** Add the fixed top client inset and a damage-aware permanent chrome paint path, translate no coordinates below the inset, and keep the modal unsaved card as the only full-client overlay. Verify editor hit testing, caret geometry, invalidation, partial repaint, framebuffer scaling, and the overlay-above-tabs order in `applicationHostTest` and `tabStripTest`; run `"production editor top chrome*"` and `"tab strip editor integration*"`.
8. **Wire tab commands into the Wayland shell.** Route Ctrl+N, Ctrl+W, Ctrl+Tab, Ctrl+Shift+Tab, tab clicks, close clicks, add clicks, and strip wheel events before editor input; bind workspace requests to portal calls and file I/O; update the tab strip, cursor, prompt subtitle, and active document after every transition. Keep `main` as the event and rendering adapter around the tested workspace. Build `scalpel-editor` and run the relevant `"document workspace*"` and `"tab strip*"` patterns.
9. **Complete the multi-document workflow checks.** Add combined tests for open-many, edit and switch, save inactive Save As completion, close dirty inactive tab, cancel a multi-dirty window close, force close, portal failure, and closing the last tab. Update `ROADMAP.md` and application architecture comments, run changed production-header checks, then run `cmake --workflow --preset dev` because the handoff crosses the application host, portal surface, chrome, and executable. A live Wayland check should cover creating, switching, saving, and closing two tabs; the full sanitizer matrix waits for the Phase 8 gate unless a memory-lifetime defect found during document retention justifies one sanitizer tree earlier.

## Completion checks

The work is complete when at least two documents can be edited, undone, scrolled, saved, and closed independently; delayed portal and clipboard work cannot affect the wrong tab; every user close path protects dirty documents; the tab strip remains usable under overflow and live scale changes; normal editor frames retain partial-damage behavior; and the remaining Phase 8 external-change policy has a per-document workspace on which to build.
