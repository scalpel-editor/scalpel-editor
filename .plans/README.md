# Local development plans

This directory separates cross-session working state from tracked product and architecture documentation. `README.md` and `TEMPLATE.md` are tracked; other files in this directory are ignored.

Create one topic-scoped plan for substantial work. State the current goal, known constraints, non-goals, intended commit sequence, and focused verification. Update it when a discovery changes the approach and make the planned commits at the appropriate points.

A plan is not an authoritative description of the code. When the work finishes, move lasting facts into current documentation, tests, code comments, or `AGENTS.md`, then delete the completed plan. Do not keep completed plans as an archive.

`ROADMAP.md` may be used locally for current and future work. It should not retain completed milestones.
