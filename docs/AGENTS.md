# Documentation instructions

These instructions apply to documentation throughout the repository, not only files under `docs/`.

- Documentation describes the current system, its constraints, and its design choices. Do not retain phase logs, completed implementation plans, source-history narratives, or verification snapshots as public documentation.
- When code removes or changes documented behavior, update or delete that description in the same commit.
- Promote lasting information from a working plan into current documentation, tests, comments, or agent instructions, then delete the completed plan.
- Do not hard-wrap Markdown prose. Write each paragraph and list item as one source line and let the editor soft-wrap it.
