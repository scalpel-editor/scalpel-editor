Introduction

This tree is the Scintilla core as refactored for scalpel-editor: a Wayland-only, UTF-8-only text editor built without a GUI toolkit. Authoritative behavior descriptions live beside named operations in scintilla/src/Editor*.cxx (and related concern files), not in this HTML file. The generated message dispatch layer has been deleted.

Document positions count UTF-8 bytes. Colours use RGB or RGBA packing as in the core types. Named methods and EditorCommand values are the editor entry points. ScintillaMessages.h has been deleted; ScintillaTypes.h and the remaining generated headers stay until phase 5 replaces or removes them.

Bidirectional layout is not on the current roadmap. Lexilla remains the intended lexer source; attach lexers through the named operations in EditorLexing.cxx.

Lexilla

Lexers live in Lexilla and implement ILexer5. This editor attaches a borrowed lexer through SetILexer and related named operations in scintilla/src/EditorLexing.cxx. The IDocument surface used by lexers remains for Lexilla compatibility; CodePage() always reports UTF-8 and IsDBCSLeadByte always returns false.

Messages with names of the form SCI_SETxxxxx often have a companion SCI_GETxxxxx. To save tedious repetition, if the SCI_GETxxxxx message returns the value set by the SCI_SETxxxxx message, the SET routine is described and the GET routine is left to your imagination.

Text retrieval and modification

Whole-document text, read-only, insertion, deletion, and range reads: scintilla/src/EditorDocument.cxx. Save point: scintilla/src/EditorHistory.cxx. Line text and allocate-lines: scintilla/src/EditorLines.cxx. Replace selection: scintilla/src/EditorSearch.cxx. Clear document style, style-at, and extended styles: scintilla/src/EditorStyling.cxx. Drag-drop enablement and change-insertion: scintilla/src/EditorInput.cxx. Named operations and their behavior descriptions live beside the definitions.

Each document byte has a style byte (together a cell). Style bytes index the style array. Document positions and lengths count UTF-8 bytes. Operations that move by characters step over complete UTF-8 sequences. Positions refer to a character or the gap before it: 0 is before the first character; after the last character is Length. The caret cannot sit inside a valid multi-byte UTF-8 character or between CR and LF of a CRLF line end. INVALID_POSITION (-1) means an invalid position. All lines share one height derived from the largest font in any current style.

SCI_GETTEXTRANGEFULL and SCI_GETSTYLEDTEXTFULL are deleted: the project uses one native position type and the typed GetTextRange / GetStyledText operations (buffer plus start and end positions). Packed text-range client structures are gone from the core; residual C client headers remain only until phase 5 step 10.

Keyboard commands

Zero-argument editing actions are EditorCommand values, not messages. The enum and dispatcher live in scintilla/src/EditorCommands.h and scintilla/src/EditorCommands.cxx (ExecuteCommand). Default key bindings map chords to those commands in KeyMap.cxx. Rebind with AssignCmdKey / ClearCmdKey / ClearAllCmdKeys in EditorCommands.cxx. Unbound keys use EditorCommand::None.

Key bindings

Default bindings live in KeyMap.cxx as KeyMap::MapDefault[], mapping key chords to EditorCommand. Named reconfiguration (AssignCmdKey / ClearCmdKey / ClearAllCmdKeys) lives in scintilla/src/EditorCommands.cxx beside the definitions. SCI_NULL as a callable message is deleted; unbound keys use EditorCommand::None.

Popup edit menu

Context-menu policy (UsePopUp / GetUsePopUp) moved to scintilla/src/EditorInput.cxx. Named operations and their behavior descriptions live beside the definitions there.

Macro recording

The record format is RecordedAction in scintilla/src/EditorRecording.h: an owned variant for commands, text insert/replace, navigation, search, and selection mode. Lifecycle, zero-argument command capture at ExecuteCommand, parameterized capture at named entry points, the host callback, and replay live in scintilla/src/EditorRecording.cxx and the concern files that emit actions. That header documents which operations are recordable, which are ignored, how text is owned, and how replay avoids recording itself. There is no numeric SCN_MACRORECORD path; hosts use the typed RecordingCallback.

SCI_STARTRECORD / SCI_STOPRECORD were replaced by named StartRecording / StopRecording operations in EditorRecording.cxx.

Printing

Print magnification, colour mode, wrap mode, and FormatRange live in scintilla/src/EditorPrinting.cxx. Named operations and their behavior descriptions live beside the definitions there. FormatRange takes document positions, a PRectangle, and platform surface handles; packed print/range client structures are gone.

Direct access

SCI_GETDIRECTFUNCTION, SCI_GETDIRECTSTATUSFUNCTION, and SCI_GETDIRECTPOINTER are deleted. They existed only to call the numeric message dispatcher without a widget send-message hop; applications call named methods on the editor instead.

Document buffer pointers remain: GetCharacterPointer is in scintilla/src/EditorTextBoundaries.cxx; GetRangePointer and GetGapPosition are in scintilla/src/EditorDocument.cxx. Behavior descriptions live beside those definitions.

Multiple views

Deleted. This editor owns one document in one window and does not expose document handles, reference counting, or multi-view attachment. There is no SCI_GETDOCPOINTER, SCI_SETDOCPOINTER, SCI_CREATEDOCUMENT, SCI_ADDREFDOCUMENT, SCI_RELEASEDOCUMENT, or SCI_GETDOCUMENTOPTIONS path.

Background loading and saving

Deleted. There is no loader object or multi-document attachment path. Load and save go through the typed document operations in EditorDocument.cxx (and later application file lifecycle code). Read-only can still lock out edits while another path reads the buffer.

Document interface

Deleted for application use. The editor owns one Document and does not expose IDocumentEditable handles to clients. Internal code may still use document types for storage and Lexilla compatibility.

Lexer

Lexer attachment, colourise, properties, keywords, substyles, style metadata, line state, and supported line-end types moved to scintilla/src/EditorLexing.cxx. Named operations and their behavior descriptions live beside the definitions there.

Lexer Objects

Lexer objects implement ILexer5 and interact with the document through IDocument. The authoritative interface declarations are in scintilla/include/ILexer.h. Editor-side attachment, colourise, properties, keywords, substyles, line state, and related operations live in scintilla/src/EditorLexing.cxx with behavior descriptions beside the definitions.

This project is UTF-8 only: IDocument::CodePage() returns UTF-8 and IsDBCSLeadByte returns false. Invalid UTF-8 bytes follow the document invalid-input policy documented on Document. Prefer LineEnd, GetRelativePosition, and GetCharacterAndWidth on the document surface for character-aware lexer work rather than hard-coding line-end bytes.

Notifications

The editor notifies its host when something the host may care about has happened. Production emission goes through Editor::NotifyParent and related helpers in scintilla/src/Editor.cxx (and concern files that call them). The deterministic test host records notifications for assertions. Filtering of modification and command events is in scintilla/src/EditorHost.cxx.

This is not a multi-platform widget document: there is no Windows WM_NOTIFY, GTK signal, or Cocoa delegate transport in this tree. Project-owned notification kinds and the flat host payload live in scintilla/src/EditorNotifications.h. The payload has no Windows notification header or message-parameter packing fields.

Deleted for this project:

  • SCN_KEY — no parent widget intercepts a numeric key notification; input uses the typed key and command path.
  • SCN_URIDROPPED — no URI drag-target host path.
  • Production SCN_MACRORECORD — recording uses the typed RecordedAction callback in EditorRecording.h / EditorRecording.cxx; there is no macro-record notification kind.

Retained event names (style needed, character added, save point, modified, update UI, margin click, dwell, zoom, hotspot, indicators, autocomplete and user-list selection, call-tip click, focus, painted, and related) still fire where the core raises them. Useful field meaning belongs beside each emission site; do not treat this HTML section as the API catalog.

Images

RGBA image width/height/scale setters moved to scintilla/src/EditorStyling.cxx (used when registering marker and autocomplete images). Marker and autocomplete image registration remain with those concerns.

GTK

Deleted. This project has no GTK embedding surface. There is no scintilla_new / scintilla_send_message widget API.

Provisional messages

Provisional message numbering and SCI_DISABLE_PROVISIONAL are transitional generated-layer concepts. Authoritative retained features are the named operations in scintilla/src. Phase 5 removes the generated message surface.

Deprecated and discouraged messages and notifications

Two-phase draw aliases (SCI_SETTWOPHASEDRAW / SCI_GETTWOPHASEDRAW) and style-bit partition messages (SCI_SETSTYLEBITS / SCI_GETSTYLEBITS / SCI_GETSTYLEBITSNEEDED) are deleted. Use SetPhasesDraw / GetPhasesDraw in EditorStyling.cxx for drawing phases; styles use full style bytes.

Edit messages never supported by Scintilla

Historical list of Windows Edit/RichEdit messages Scintilla never implemented. Not part of this project's API; kept only as a short note that those messages have no effect.

Removed features

Historical removals from upstream Scintilla (palette mode, style-byte indicators) plus deletions made in this tree (encoding, multi-view documents, direct-call accessors, renderer selection, and other platform-only paths). See MESSAGE_REMOVAL.md for the phase 4 deletion ledger. Authoritative remaining behavior is beside named operations in scintilla/src.

Building Scintilla

Build and test this repository from the root with CMake presets, not with upstream SciTE or platform widget build files. Configure once with cmake --preset dev, then build and run the focused unit and editor tests as described in AGENTS.md. The core builds as static library scintilla_core. The full local check matrix is ./check.sh (normal, AddressSanitizer, and UndefinedBehaviorSanitizer trees).
