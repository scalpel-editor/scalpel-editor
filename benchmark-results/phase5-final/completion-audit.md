# Phase 5 final completion audit

## Durable index and corpus

All 91 C++ source and header files changed since the Phase 4 completion commit were individually confirmed in grepai's durable index. Later audit corrections to `EditorSearch.cxx`, `EditorNotifications.h`, and `Editor.cxx` were also explicitly waited on before the final snapshot. The recorded index is steady, matches the live configuration, and contains 199 files and 1,921 chunks. `tools/discoverability/check-corpus.sh` reports 60 rows with valid final targets, definition markers, and evidence files.

## Message-layer removal

`tools/check-no-message-layer.sh` reports every category clean: no `WndProc` / `DefWndProc`, generated message-layer file, `ScintillaMessages.h` reference, `Message::` case or cast, `enum class Message`, non-allowlisted `SCI_*` / `SCN_*` constant, message-layer generated-section marker, coercion helper, client packing type, or live documentation directing calls through messages. `scintilla/include` now contains only the retained Lexilla contracts `ILexer.h`, `ILoader.h`, and `Sci_Position.h`.

The narrow same-spelling allowances are recorded in `tools/phase5-boundary.md`: `SCI_METHOD` for the Lexilla calling convention and its implementations, `SCI_POSITION_H` for that retained header's guard, `SCI_OWNREGEX` for the built-in regex selection, and autogenerated markers in the retained Unicode category and case-conversion tables. The gate checks exact token/path pairs instead of excluding whole source files.

An additional repository search finds no live `CharacterRange`, `CharacterRangeFull`, `TextRange`, `TextRangeFull`, `TextToFind`, `TextToFindFull`, `RangeToFormat`, `RangeToFormatFull`, `NotifyHeader`, `uptr_t`, or `sptr_t`. Historical records remain only in the files excluded by the completion gate.
